# macOS management companion (`md-pep3`, `md-qgxe`)

This is the native AppKit counterpart to the [Linux manager](../manager.md), not a port of GTK. The host CLI and SDL overlay remain independent. The companion can launch a reviewed client connection, but never starts a host or enables sharing. Closing it does not stop the host. See the [macOS Manager guide](../manager-macos.md) for current workflows. See the [management UX plan](management-ux-2026-11-14.md) and [host lifecycle](../host-lifecycle.md).

## Build and layout

With the normal macOS core dependencies and a built, pinned nostrc tree:

```sh
meson setup build-mac-manager -Dmacos_manager=true -Dclient=true \
  -Dsigner_nip5f=true -Dsigner_nip46=true \
  -Dnostrc_root="$NOSTRC" -Dnostrc_build_dir="$NOSTRC/_build"
meson compile -C build-mac-manager
meson test -C build-mac-manager --suite macos_manager --print-errorlogs
```

`-Dmacos_manager` is off by default and macOS-only. It enables no GTK or libadwaita dependency. The prototype bundle requires macOS 13 or later for its System Settings pane links; this does not change the host's OS floor. The host-side `host.permissions` v1 wire extension and shared ScreenCaptureKit/AX preflights ship in **every macOS host build**, independently of this option. The build produces `build-mac-manager/src/macos_manager/Metadesk Manager.app` (`Contents/{Info.plist,MacOS/metadesk-macos-manager}`). It uses build-tree libraries; it is not installed, relocatable, or added to the release DMG. The [packaging plan](packaging-2026-11-21.md) keeps the shared private library closure and existing host/client products; release integration, Developer ID, notarization, and the stable host helper/TCC identity are separate (`md-wdi3`). The prototype is not a gate on the current host/client DMG.

## Pages and core boundaries

| Page | Current | Follow-up |
| --- | --- | --- |
| Hosts | `hosts_model.m` drives `MdStoreController` with the saved client binding. `hosts_page.m` projects cached and live hosts, quick connect, reviews, revisions, tags, exchange and conflict actions. A file-only QR scan feeds the same input classifier and trust review as typed addresses. `hosts_launch.m` owns client discovery and private-channel progress. | Signed on-screen qualification, including bootstrap preference retention and clear-to-offline, and scan-to-review. |
| This Computer | `access_model.m` subscribes over verified same-user IPC. `access_page.m` renders lifecycle, reachability, live session state and kick, with explicit `host.permissions` preflight and Settings links. It can show the saved host role's public `nprofile` QR without contacting a signer. | No IPC sharing/unattended setters or documented in-app agent start/stop. Signed registration/helper identity belongs to `md-wdi3`. |
| Access | Pending request reviews, once/remember/deny, exact remembered policy editing and revoke, and kick-and-revoke. Only requested and supported video is initially selected. | Qualify native sheets and notifications on a signed, already-authorized build. |
| Identity | `identity_model.m` and `identity_page.m` add and relabel public metadata for compiled external signer backends, import an already-paired NIP-46 credential through the credential store, require live signer verification to bind, check the actual daemon node key for FIPS, and unassign/remove through `MdAccounts`. Client mutations drain the Hosts binding and reload it under the saved owner. | Key creation and key import remain in the external signer. Grotto signer-status integration is not in the AppKit app. A running host adopts role changes only on restart. |
| Relays | The tab remains an offline preview. Hosts loads and saves explicit bootstrap choices through the same `manager-relays.ini` codec as GTK. Loading does not start sync; explicit refresh applies the configuration. An empty list starts no management relay activity. The shared core owns identity resolution, discovery, delivery and write plans. | A dedicated relay configuration/status page is not part of this slice. |
| Activity | Points to live session state and disconnection in This Computer. | No separate activity history. |

AppKit owns the main thread. Hosts serializes its account, signer, resolver, file and controller work on a worker queue. Controller callbacks coalesce into refresh hints; the page does not poll for history or publication. Refresh or shutdown tears down the old controller, bridge and signer on that queue; quit waits for drainage. Decrypted C buffers and Jansson trees are scrubbed; bounded Foundation projections live in process memory and are not explicitly zeroed. No address-book plaintext is persisted by the frontend except an explicit warned export. The window is not restorable, and Hosts text editors do not copy book data; the explicit copy action writes a public key only. The configured signer may need its own network and user approval even to read offline cache. There is no Metadesk password: unlock in the external signer, start a missing socket signer, or handle remote signer approval there. Live signer lock/transport state is not inferred from saved metadata. Local NIP-46 credential errors are reported separately from remote signer failures: an unsigned build without access to the saved item's Keychain ACL can fail before reaching the signer. The core lookup does not request Keychain UI. Pairing import accepts masked single-line JSON in memory, checks the saved account's exact public key, and uses the existing Keychain backend. No import/export file, clipboard workflow, or plaintext storage is provided.

## Hosts trust and private client channel (`md-qgxe`)

The Darwin client now accepts `--managed-session-fd` as its only option in a managed launch. The AppKit Hosts launch worker finds an executable beside the manager, inside the bundle or on `PATH`, calls `md_managed_launch_spawn`, sends the reviewed config and consumes versioned progress and outcomes. It bounds per-turn reads and deduplicates progress/relay diagnostics before dispatching to AppKit. Darwin uses a same-user Unix stream: a bounded big-endian configuration length followed by JSON, then single-byte versioned status/command messages. Linux keeps Unix `SOCK_SEQPACKET` and its existing wire format. Windows still has no managed launch channel.

Darwin's spawn explicitly maps the child endpoint to descriptor 3, attaches standard streams to `/dev/null`, and uses close-on-exec by default for the remaining descriptors. It resets the child's signal mask and the TERM, INT, HUP, PIPE and CHLD dispositions rather than inheriting the manager worker's signal state. The parent endpoint is nonblocking so a child that never reads configuration cannot defeat the five-second framing deadline. A Darwin process-exit source reaps the child without retaining a blocked worker for the life of the video session. The environment forwards only runtime locations; no signer secret or pairing goes through the channel, arguments or environment. The client validates local peer credentials and independently restores and checks the saved signer. Callers own the parent endpoint and must reap children, including failed launches. The worker must remain responsive to cancellation and distinguish an unfinished launch from an already connected session before tearing down the channel.

Review requires EOSE on connected fetch routes, not success on every configured route. Writes require EOSE on every required fetch route. Launch checks the reviewed revision and owner again and refuses an alias mismatch. An accepted replacement carries label, notes, favorites and tag memberships; the user reviews again before connecting. Pending Hosts/metadata changes cannot make retired pins selectable. Collection edits remain separate acknowledged operations. Host-agent controls remain out of scope. Do not use a standalone `launchctl bootstrap` of the packaged `BundleProgram` plist as a substitute for the signed registration flow in [host lifecycle](../host-lifecycle.md#macos-bundle).

## Local authority and signer lifecycle

IPC v1 stream frames are full snapshots. The first subscription frame is authoritative; out-of-order revisions do not roll state back. A revision gap temporarily disables commands and reconciles against an independently authenticated `management.snapshot`; a changed generation or failed reconciliation clears authority and requires explicit reconnect. Request decisions carry the reviewed generation and revision, and editing policy also carries its writer version. Remembering checks the local policy version before sending the exact v1 approval command. An acknowledged `access.remove` already revokes matching admission; the UI does not sequence an unconditional kick with a separate policy mutation. The countdown is local presentation, not a refresh timer or an authorization source.

Only a signature with a team identifier and already-authorized macOS notifications enables delivery. Notifications have no approval action; the open action rechecks the exact generation/request ID and expiry. Inbox removal withdraws pending and delivered notices, and a posting failure is bounded to one retry. Unsigned fixtures test token eligibility but do not post system notifications.

Role writes run on a worker with a stale-selection check under the account writer lock. Role selection does not persist signer credentials. FIPS binding uses `show_status` and the same core identity check as the host. A failed verification does not save the candidate. Cancel invalidates a pending save; an already-running signer call may still need to finish. The app does not infer signer lock state from an unavailable transport or prompt to unlock Keychain. Client mutations drain the old controller and binding before saving or removing the account, then reload Hosts. Quit and session termination defer the original AppKit termination request while worker ownership drains. A five-second deadline bounds how long logout can wait for a non-interruptible transport call. Current missing features and the future on-screen checklist are in the [macOS Manager guide](../manager-macos.md).

## Permission onboarding

1. Start the already provisioned host as its intended user-session identity using the CLI or configured supervisor. Enter its [management socket](../host-management.md) and select **Connect to Local Host**, then **Recheck Permissions**. Only that authenticated IPC peer reports permissions; the GUI never checks its own grant and attributes it to the host.
2. **Allowed** is a positive preflight; **Not allowed** combines never-granted, denied and revoked because the APIs do not distinguish them. **Unknown** means no trusted, supported report, not absence of permission. Values are snapshots, not monitored status. The ScreenCaptureKit and AX backends and IPC use the same `CGPreflightScreenCaptureAccess` and `AXIsProcessTrusted` checks. These do not request consent. AX trust is not a probe of Quartz event delivery; the CGEvent backend's event creation is not used as a permission detector.
3. The corresponding button opens the Screen Recording (Screen & System Audio Recording on newer releases) or Accessibility pane. If the link fails, use **System Settings › Privacy & Security**. The URLs are best-effort OS integration; the operator grants the *responsible host identity*, not the manager. Terminal-launched and bundled agents may have different responsible identities. Restart the host if macOS requires it, then reconnect and select **Recheck Permissions**. Neither a grant nor opening Settings enables sharing or authorizes a remote client.

The manager does not request permissions, start a capture to test them, query the accessibility tree, or post an input event. Headless tests cover the verified socket with a fake host, including permission state, gap recovery and exact decisions, and the account model with a fixture signer and credential store under an isolated HOME, including public metadata edits, credential-only pairing import, and role-binding refusal. The Hosts suite covers input classification, launch mapping and executable discovery, private-channel cancellation under repeated child diagnostics, and the real controller with a fixture signer and a private loopback relay. It does not qualify an on-screen AppKit review, a real video window, production signer access, or native permissions. The QR fixture round-trips a saved public host role through Core Image and Vision, checks secret classification, and rejects unsupported/oversized inputs without opening a file picker or camera. An in-process AppKit fixture drives the real Hosts, Access and Identity controls and sheets with injected models, and exercises the `main.m` termination delegate while a Hosts operation is blocked. It checks what reaches the model, including no stale approval or implicit pin replacement. The fixture uses off-screen windows, no synthetic input, no screenshots and no accessibility permission. `account_keychain` covers the file-based credential API with an explicit private file and no login Keychain or search-list operations. A real screen/Settings flow, production signer access (including its Keychain ACL), and signed helper attribution require separate interactive qualification.
