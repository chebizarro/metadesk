## Integration and md-w24o

Host conflict resolution retains W3's standalone `--fetch-openh264` before
capture/signer/thread startup, inside W1's process-terminal shutdown wrapper.
Client tests retain W6's complete signal, overlay/grants and FIPS dial/backoff
coverage plus W1's ordered TCP input-grant regression. W6 client semantics and
the common `MD_CAP_INPUT` sender gate remain intact.

**md-w24o is in W1's stream/client area.** The cancelled bind was waiting in
Windows `WSAPoll`; local socket `shutdown` did not wake that readiness wait.
The unchanged regression received SESSION_INFO, cancelled, then failed its
**<2 second** assertion only after the five-second ACK deadline. W1 reproduced
this on the merged tree with corrected MF: **5.31 seconds** for the test program.

Fix **4598d62** gives each Windows stream a private loopback wake pair, polled
alongside the transport. `md_stream_close` sets terminal state and signals
persistent readiness, including cancellation racing entry into a wait. Windows
plain and TLS readiness waits share it; POSIX retains native shutdown wakeup.
All pair handles are acquired/closed with stream ownership; the accepted local
peer is checked against the writer endpoint. No per-packet relay polling,
retry-to-green, delay or timeout increase is involved.

Client cancellation now uses that close API under the existing candidate
ownership mutex. The binding worker still exclusively destroys its candidate.
A current-owner/cancellation check under the same mutex also closes the
cancel-before-candidate-publication hole. The regression covers both cancellation
before publication (no proof emitted) and cancellation after peer receipt of
proof, retaining the original <2 second assertion. Windows final client program:
**98 checks, 0.227 seconds**. Additional predeclared batch: **20/20 native exits
0**, 98 checks each, **0.113–0.156 seconds** during the final measured GUI soak
(no sample retried).
